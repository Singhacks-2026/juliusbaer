Wealth Intelligence — System Architecture

The intelligence layer between portfolio data and the Relationship Manager. A deterministic engine computes every signal from the book; a language model only explains those signals. The separation is the compliance story: no insight an RM cannot defend in front of a client, and no number a model invented.

Interface — Streamlit RM workbench Core — pure standard-library Python Book — 20 clients · 24 portfolios · 1,015 positions Signals — 6 detectors · Σ severity² triage Data — synthetic, 5 dated snapshots
Python · stdlib core Streamlit · workbench Claude API · Opus · explanation only unittest · 16 regression tests CSV / JSON · 12 source files event_log.csv · authoritative events

Fig 1 · the pipeline

Signal → understanding → decision

The book flows down one path. Everything above the governance line is deterministic and auditable; the model sits below it and is handed facts, never asked to compute them.

Components

What each part is responsible for

ComponentResponsibilityModule
Data modelLoad and join the 12 files into one currency-aware, indexed Book; convert every value to USD from holdings.market_value_usd.data_model.py
Look-throughResolve a stock, its perpetual and structured products to the single issuer they really expose the client to.lookthrough.py
DetectorsSix deterministic signals: collateral, concentration, mandate & exclusion, liquidity, income & drawdown suitability, event attribution.detectors.py
EngineRun every detector across the book and rank clients by Σ severity² — the triage.engine.py
ExplainerGrounded natural-language read via Claude; cached to disk, deterministic fallback offline.explainer.py
WorkbenchThe three-zone RM interface: triage → client story → accept/edit/dismiss.streamlit_app.py

Key design decisions

Why it is built this way

DecisionRationaleWhat it costs
Deterministic engine; the LLM only explainsEvery insight is defensible in a compliance review — the numbers come from files, not from a model's memory.An extra layer to build; the model can't surface a signal the detectors don't encode.
Pure standard-library coreRuns anywhere a bank permits Python — no pip install for the engine, trivial to audit and deploy.A little CSV and FX plumbing written by hand.
Value from market_value_usd, never the base-currency AUM columnsAvoids reading a HKD→USD conversion as a loss (Lau's book "falls" 206m→26m only on paper).None — it is simply the correct column.
Look-through via an explicit alias tableAuditable: no free-association about what a structured note references.A curated map to maintain as the instrument universe changes.
Custody separated from managedA client-directed legacy stake is a concentration to discuss, not a mandate breach to correct.Slightly more logic in the concentration detector.
Explanations cached, with an offline fallbackA live demo cannot depend on venue wifi; the app always works.Cached text is keyed by a hash of its inputs so it regenerates when they change.
